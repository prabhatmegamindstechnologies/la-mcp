## Tool design

| Tool | Inputs | Annotations | Returns |
|---|---|---|---|
| `search_service_requests` | `plant?` (name/ID, partial match), `status` open/closed/all (default open), `limit` 1–50 (default 20) | readOnly | count + compact list (id, title, plant, status, priority, createdAt) |
| `get_service_request` | `id` | readOnly | full record, or a clear "not found" error (`isError: true`) |
| `create_service_request` | `plant`, `title` (3–120 chars), `description` (≤2000), `priority` low/medium/high | readOnly=false, destructive=false, idempotent=false | the created record with new id |

Descriptions written for the AI ("Use when the user asks…"). Sample data clearly labelled as sample in tool output.

## Security (PoC level)

- Bind to `127.0.0.1` only; no auth yet (Phase 3) — README warns not to expose via tunnel with real data.
- zod validation + length limits on all inputs; `express.json({ limit: "100kb" })`.
- No secrets or env tokens needed.
- Errors returned as tool errors, no stack traces to client.
